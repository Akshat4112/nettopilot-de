# NP-UX-007 — Matched optional offer categories

Both base salaries, frequencies and copy/clear controls come first. Five initially closed native details disclosures pair Offer A and Offer B: cash compensation, working time/vacation, commute costs/time, remote/home-office terms and pension/benefits. At narrow widths A precedes B within each category. Every field keeps its original label, help and error associations. Closing a category never clears it; copying and clearing still include every category.

Summary statuses are presentation-only and derived from current raw entries. Not supplied means no own category fields were entered; shared schedules alone never supply commute or remote terms. Incomplete means entered terms are invalid or lack required dependencies. Supplied means entered terms pass existing validation, not that every optional field is known or included in payroll. Cash metadata alone is incomplete. Commute cost and time branches are independent: entering one never requires the other, but each entered branch must have its workday/office-day/vacation prerequisites. Explicit zero remains valid only where existing validators accept it. Unknown money never becomes zero.

No payroll rules, calculation action, storage, URL sharing or dependency changes. Native disclosure keyboard behavior and focus styling remain available. Tests open the same categories through user clicks or keyboard actions before interacting with fields. Verification covers per-category statuses, copy/clear and closed values, existing semantic/error checks, current comparison summary, 375px keyboard operation and 1280px paired layout.
